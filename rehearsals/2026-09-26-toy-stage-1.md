# Rehearsal 1 — toy, stage 1 (Sep 26–27)

The first time the four seats ran the whole loop on something real: the unscored `toy`
track's stage 1, a shared counter over HTTP. The goal was to find out whether the
seats plan, build, verify, audit and commit without help, before a spec that counts.

**Result:** stage 1 committed as the rehearsal repository's first commit, approved by
the Verifier (16 checks) and signed off by the Spec Auditor. `harness check` reported only
the files a rehearsal repository never had (README, FACTORY, room.json). **But a human
had to step in twice**, and in a submitted run either intervention costs the Autonomy
half of Agent Teamwork. Those two stalls are the main lesson.

Gate 3 was not tested: the laptop used has no Docker. The Verifier started the service
with Python directly instead.

**Independent check, afterwards and outside the band:** the organizers' stage-1 suite
(8 checks), run with pytest against a fresh clone of the committed revision started with
Python, passes 8 of 8. The Verifier's approval, made on checks it derived itself, matched
the official suite.

## What went wrong, and what changed

**0. The lead seat could not start.** The first two turns failed before any work: a
permission-mode conflict (Band's error suggests a managed settings policy or a local
`permissions.defaultMode` overriding the seat), then Claude Code not being signed in. Two
"try again" messages got past it. In a submitted run those are steering, and a second
dispatch is a rerun.
→ Not a mandate problem. Before the submitted dispatch, run `band preflight`, then wake
every seat once in a scratch room and see a clean turn from each. Only then open the
fresh room.

**1. A written handoff was lost.** The Builder's reply was staged, to post when its turn
ended. The turn then ended on an error from a test server the Builder had left running in
the background, and the staged reply was dropped. Nothing was queued anywhere, so nobody
was woken.
→ Seats run checks as one foreground command, stop every process before handing off, and
make the handoff the last thing a turn does. The Architect keeps a list of open handoffs
and re-sends any a seat has not answered.

**2. A seat died silently.** The Verifier hit an out-of-credits error. The error was
visible in the room, but the Architect was never woken to see it.
→ The Architect checks open handoffs every turn and re-sends to a seat whose turn ended in
an error. Outside the mandates: each seat's model needs enough quota for a full run, with
a fallback (an API key) arranged in advance. A mandate cannot fix an empty account.

**3. Extra behaviour passed three reviewers.** The Builder added request-size limits,
chunked-body parsing, a 30-second timeout and 405 responses. It listed them honestly as
things no criterion exercised. The Architect accepted them, the Verifier approved them and
the Spec Auditor reported that "backward traceability accounts for everything delivered".
The cause was in the mandates: the Builder was told both "never add unrequested behaviour"
and "handle bad input deliberately", with no line between the two.
→ The Builder's rule now says what failure handling does and does not license. The
Architect records or returns every behaviour the Builder chose. The Spec Auditor rejects
unaccounted behaviour instead of noting it.

**4. The mandates disagreed about routing.** The Builder's mandate handed off to the
Verifier; the Verifier's said it took work from the Architect. The run went Builder →
Architect → Verifier, which worked, because only the Architect's request carried the full
requirements.
→ All mandates and FACTORY.md now describe that route, with fixes going straight back
from Builder to Verifier.

**5. The Architect committed everything at the end.** The guide expects the implementer to
commit and post revisions, with commits made along the way. The commit was authored as the
human.
→ The Builder commits each working increment under its own seat name; nobody rewrites history.

**6. A mention that was typed, not picked, went nowhere.** In Band Desktop, `@builder`
typed as plain text did not become a mention, so the Builder never saw the message. (The
Architect saw a real mention of itself in the same message and relayed it — good
behaviour, and luck.)
→ Dispatch note: pick every handle from the suggestion list. `band room send --mention <id>`
does it from a terminal.

## What worked

- The Architect planned before delegating, traced every criterion to a spec passage, and
  recorded its assumptions in the room instead of asking the human.
- Every handoff carried the complete specification, split into numbered parts with the
  last marked final. The Verifier correctly waited for part 2 before starting.
- Milestone isolation held: the Builder deleted scaffold code from a later concern
  (accounts and passwords) instead of leaving it unrouted, and the Auditor confirmed it on disk.
- The Verifier re-ran every Builder claim itself instead of trusting the report.

## Tried and dropped: an Antigravity seat

A fifth seat running Google's Antigravity CLI (`agy`) through a hand-written ACP bridge
was built and connected. It passed Band's startup handshake but never ran a prompt, and
the bridge had no memory between messages, a ~32 KB prompt limit from the Windows
command line, no model pinning and no permission sandbox. Band's native transports are
Claude Code, Codex, Copilot, OpenCode and ACP, and `agy` speaks none of them itself. The
rubric does not reward vendor count, so the seat was stopped and taken off the roster.
A second provider is worth revisiting only through a transport Band supports natively.

## Not yet proven

- **The Verifier running `harness run` itself,** as the guide expects of the reviewer.
- **A run with no human input at all,** across several stages from a single dispatch.
- **The fixes above.** They are untested until the next rehearsal.
